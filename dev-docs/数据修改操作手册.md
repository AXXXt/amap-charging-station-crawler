## 0. 先看这段：HENAN 任务只看 MySQL，SQLite 已彻底摘除

本次改动来自提交 `10e5eab`（"将 HENAN 任务调度切换为 MySQL 权威源"）及其后续收口。**改动前的文档、口头经验、旧脚本注释里的"SQLite 是权威源""改完要同步 SQLite"已全部作废。**

| | 变更前（旧） | 变更后（现在） |
|---|---|---|
| **HENAN 任务**权威源 | ECS 上的 SQLite | **远程 MySQL** `henan_heavy_truck_charging_station_task` |
| MySQL 任务表角色 | 展示镜像（改了会被覆盖） | **唯一权威源**（改了立即生效，重启不回滚） |
| SQLite 角色 | 权威源 | **已从 HENAN 链路摘除**：不读、不写、不回灌（残留行只是历史快照） |
| 同步方向 | 运行期单条 SQLite → MySQL | **无同步**。新任务只经 `admin/henan-poi/import` 直写 MySQL |
| 重启影响 | 用 SQLite 快照覆盖 MySQL，进度"倒退" | **不影响任务状态**（`startup()` 只读确认表可用并统计条数） |
| 手机端 claim/ack/progress/complete/fail | 读写 SQLite | 直连 MySQL 事务 + 行锁 + 租约校验 |

**非 HENAN 的数据没有变**：`SITE_STATION_DETAIL` / `REGION_SCAN` 任务、设备表 `collector_device`、`station_observation` 仍然以 ECS 上的 SQLite 为准。

### 0.1 两条最容易踩的坑

1. **查 SQLite 看 HENAN 进度 = 看一份早已废弃的旧快照**。真实进度只在 MySQL 里，别再看 SQLite。
2. **时间列必须写 `UTC_TIMESTAMP()`，不能用 `NOW()`**：该表时间列全库按 **UTC** 存储，api_server 的 claim / reaper 也按 UTC 比较。写成本地时间（本环境 +08:00）会让 `available_at` 晚 8 小时，**任务迟迟领不到**（2026-09-16 真实踩过）。

> ❌ 已作废的旧说法：「只改 MySQL 会被重启回滚，所以要两个库一起改」。现在**只改 MySQL 就够了**，重启不会回滚。

### 0.2 三分钟上手（先看这段）

```bash

ssh root@116.62.103.230 'cd /opt/amap-crawler && python3 -c "
import re,pymysql
url=re.search(r\"^EVCS_DATABASE_URL=(\S+)\",open(\".env\").read(),re.M).group(1).strip().strip(chr(34))
m=re.match(r\"mysql://([^:]+):([^@]+)@([^:/]+):(\d+)/(\S+)\",url)
c=pymysql.connect(host=m.group(3),port=int(m.group(4)),user=m.group(1),password=m.group(2),database=m.group(5),charset=\"utf8mb4\")
cur=c.cursor(); cur.execute(\"SELECT status,COUNT(*) FROM henan_heavy_truck_charging_station_task GROUP BY status\"); print(cur.fetchall())"'

# ② 需要把"已完成"的任务重新跑一遍时（默认 dry-run，只统计不写库）
ssh root@116.62.103.230 'cd /opt/amap-crawler && python3 reset_tasks.py'

# ③ 确认无误再执行（只写 MySQL 这一张表；建议先自行 mysqldump 留档）
ssh root@116.62.103.230 'cd /opt/amap-crawler && python3 reset_tasks.py --apply'
```

**只要记住一句话**：HENAN 任务状态**以 MySQL 为唯一权威源，改它就够了，重启也不会回滚。**

## 4. 常用操作

### 4.1 看状态分布（只读，随时可做）

```bash
# ★唯一权威源（真实进度）—— 只看它
ssh root@116.62.103.230 'cd /opt/amap-crawler && python3 -c "
import re,pymysql
url=re.search(r\"^EVCS_DATABASE_URL=(\S+)\",open(\".env\").read(),re.M).group(1).strip().strip(chr(34))
m=re.match(r\"mysql://([^:]+):([^@]+)@([^:/]+):(\d+)/(\S+)\",url)
c=pymysql.connect(host=m.group(3),port=int(m.group(4)),user=m.group(1),password=m.group(2),database=m.group(5),charset=\"utf8mb4\")
cur=c.cursor(); cur.execute(\"SELECT status,COUNT(*) FROM henan_heavy_truck_charging_station_task GROUP BY status\"); print(cur.fetchall())"'

# 是否有任务正在被采集（★改库前必看）：LEASED/RUNNING 非空时不要做全表重置
ssh root@116.62.103.230 'cd /opt/amap-crawler && python3 -c "
import re,pymysql
url=re.search(r\"^EVCS_DATABASE_URL=(\S+)\",open(\".env\").read(),re.M).group(1).strip().strip(chr(34))
m=re.match(r\"mysql://([^:]+):([^@]+)@([^:/]+):(\d+)/(\S+)\",url)

cur=c.cursor(); cur.execute(\"SELECT lease_device_id,status,COUNT(*) FROM henan_heavy_truck_charging_station_task WHERE status IN (%s,%s) GROUP BY lease_device_id,status\",(\"LEASED\",\"RUNNING\")); print(cur.fetchall())"'
```

> 参考（非权威，仅用于看**非 HENAN** 任务的真实状态）：`sqlite3 /opt/amap-crawler/data/mobile_control.db "SELECT type,status,COUNT(*) FROM scan_task GROUP BY type,status;"` —— 其中 `HENAN_POI_DETAIL` 那些行**是废弃快照，别拿它判断进度**。

任务类型：`HENAN_POI_DETAIL`（河南 POI 明细）、`SITE_STATION_DETAIL`（站点详情）、`REGION_SCAN`（区域扫描）。
状态：`PENDING` 待领取 / `LEASED` 已领取 / `RUNNING` 采集中 / `COMPLETED` 已完成 / `FAILED` 失败（进补采）。

### 4.2 重跑数据：把「已完成」改回「待领取」★最常用

**首选：用云端脚本**（默认 dry-run，只写 MySQL 权威表；立即生效且重启不回滚）：

```bash
ssh root@116.62.103.230 'cd /opt/amap-crawler && python3 reset_tasks.py'                              # ① dry-run：先看要改几行
ssh root@116.62.103.230 'cd /opt/amap-crawler && python3 reset_tasks.py --apply'                      # ② 执行
ssh root@116.62.103.230 'cd /opt/amap-crawler && python3 reset_tasks.py --apply --include-failed'     # 变体：连 FAILED（补采）一起归零
ssh root@116.62.103.230 'cd /opt/amap-crawler && python3 reset_tasks.py --apply --from COMPLETED,RUNNING'  # 变体：自定义要归零的源状态
```

**脚本真实行为**（只有一步，且只动一张表）：

| 步骤 | 动作 | 效果 |
|---|---|---|
| ① | 统计当前 MySQL 权威表各状态条数（`--apply` 前是 dry-run） | 先看清要改多少行 |
| ② | 在 MySQL 上把 `status ∈ {COMPLETED}`（或 `--from` 指定值）**重置为 PENDING** | **立即生效**：手机端下一次 claim 即可领到 |

重置时一并清空的字段：`lease_device_id` / `lease_token` / `lease_expires_at`（租约）、`attempt` / `recovery_attempt`（尝试次数）、`progress` / `result_summary`（进度），避免手机端拿着陈旧租约继续上报（会导致 409 与 outbox 卡死）；时间列写 `UTC_TIMESTAMP()`（见 §0.1 坑 2）。

> ⚠️ **脚本不再触碰 SQLite**，也没有 `--mirror-only` / `--skip-mirror` / `--types` 这些旧参数（那是"两个库一起改"时代的产物，已删除）。它只操作 `henan_heavy_truck_charging_station_task`。

**手工等价 SQL（理解用）**：新架构下**只需改 MySQL 这一张表**。

```sql
-- 时间列必须用 UTC_TIMESTAMP()，不能用 NOW()（见 §0.1 坑 2）
UPDATE henan_heavy_truck_charging_station_task
   SET status='PENDING', attempt=0, recovery_attempt=0,
       lease_device_id='', lease_token='', lease_expires_at=NULL,
       started_at=NULL, finished_at=NULL, last_error='',
       progress=NULL, result_summary=NULL,
       available_at=UTC_TIMESTAMP(), updated_at=UTC_TIMESTAMP()
 WHERE status='COMPLETED';
SELECT ROW_COUNT();     -- 看更新行数
```

-- ③ 改完复查：期望 COMPLETED 归零、PENDING 相应增加

## 5. 纪律：四条铁律 + 四条禁止

**铁律**

1. **HENAN 任务唯一权威源 = MySQL**：看进度看它，改状态改它；SQLite 上的 HENAN 行已废弃。
2. **改状态只改 MySQL 就够**（推荐 `reset_tasks.py --apply`）：立即生效，重启不回滚；**不要再"顺手同步 SQLite"**。
3. **时间列必须写 `UTC_TIMESTAMP()`**：全表按 UTC 存储，claim/reaper 也按 UTC 比较（§0.1 坑 2）。
4. **改前看 `LEASED`/`RUNNING`、改前 `mysqldump` 留档、改后复查状态分布**。

**禁止**

1. 🚫 不要在图形客户端里改了表却不提交（**现在会直接掐断手机端采集**）；
2. 🚫 不要在手机正在大批量领取任务时做全表重置（先确认 `LEASED`/`RUNNING`，必要时 `systemctl stop amap-api`）；
3. 🚫 不要把 `EVCS_DATABASE_URL` 里的口令贴到群里/截图里；
4. 🚫 不要手改 `site_exploration_charging_station_result` 之外的结果表然后指望"自动同步"—— 该表是 upsert 写入，重跑即覆盖，手工改动要自己想清影响面。

**留痕**：任何改状态的操作，请在 `cloud_service_ops.md` §10.5 的「实操留痕」表里补一行（时间 / 操作 / 备份文件名 / 执行人）。

## 6. 排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 本机连不上 `121.41.56.201:3306` | 网络/白名单/防火墙 | 找管理员加你本机出口 IP；确认账号 host 允许（`'user'@'%'`） |
| MySQL 报 `1205 Lock wait timeout` | 有未提交事务锁着表 | ★**现在会导致手机端 500**。用带 `PROCESS` 权限的账号查并杀：<br>`SELECT trx_mysql_thread_id, TIMESTAMPDIFF(SECOND,trx_started,NOW()) FROM information_schema.INNODB_TRX;`<br>`KILL <thread_mysql_thread_id>;` |
| 手机端 claim/ack 返回 **500** | ① MySQL 锁表（1205）② 代码异常 | 先看日志：<br>`ssh root@116.62.103.230 "journalctl -u amap-api -n 100 --no-pager \| grep -A 5 'Traceback'"`<br>若是 `1205` → 按上一行杀事务，**本次架构后没有兜底，必须解锁才恢复**；<br>若是 `TypeError: the JSON object must be str...` → 见下方"已修历史问题" |
| 手机端报「服务端未确认 N/M 条采集结果」 | 结果上报的任务状态读错源 / 租约校验挡在幂等之前（2026-09-16 已修） | 见 `cloud_service_ops.md` §11.8。若仍复现，先查该任务在 MySQL 里的 `status` 与 `lease_token` |
| 手机端提示无任务 | 权威源（MySQL）里可领任务为 0 | 按 §4.1 查 MySQL；需要补充待领取任务按 §4.2 重置 |
| 服务异常 | —— | `systemctl status amap-api` / `journalctl -u amap-api -n 50 --no-pager` / 重启 `systemctl restart amap-api`（**启动约 2 秒，不影响任务进度**） |
| 权限不足无法看到锁 | `evcs_u` 无 `PROCESS` | 申请带 `PROCESS` 的账号，或请管理员代查 |

### 6.1 已修历史问题（2026-09-16）

**① 手机端 claim 全片 500：`TypeError: the JSON object must be str, bytes or bytearray, not dict`**

- 现象：`POST /api/v1/device-tasks/claim` 返回 500，日志堆栈指向 `_mobile_task_payload()`。
- 根因：新架构下 `_henan_mysql_row_to_task()` 用 DictCursor 读 MySQL，JSON 列已被解码成 `dict`；而 `_mobile_task_payload()` 仍按 SQLite 的约定无条件 `json.loads()`。
  因为 `_mobile_task_payload()` 是所有手机端接口的**唯一出口**（18 处调用），所以 claim/ack/progress/complete/fail 会一起崩。
  触发条件很隐蔽：**任务 `progress`/`result_summary` 为空时正常，一旦手机上报过进度就必崩**。
- 修复：新增 `_payload_object()` 兼容"JSON 字符串 / 已解码 dict / None"，替换了三处无条件 `json.loads()`。

**② 结果上报 outbox 死锁**：任务状态"SQLite 优先"读错源 + 租约校验挡在幂等之前，导致已落库的结果永远无法被确认。修复为「权威源优先 + 幂等前置」，详见 `cloud_service_ops.md` §11.8。

## 7. FAQ

**Q：我只在自己电脑上操作，行不行？**
A：可以。查数据、改**任务状态**都能在本机直连 MySQL 完成——这正是新架构带来的便利，**改完不需要再同步任何地方**，也不会被重启回滚。

**Q：我直接改 MySQL 那张任务表，看着也变了啊？**
A：对，**而且立即生效、重启也不会被刷掉**（这正是新架构的设计）。用 `reset_tasks.py --apply` 更省事，它会自动清空租约与进度。

**Q：我按老文档改 SQLite 为什么没反应？**
A：因为 HENAN 任务**已经完全不读 SQLite** 了，改它不会有任何效果（那只是一份废弃快照）。请改 MySQL。

**Q：改完要不要重启服务？**
A：**不需要**。手机端下一次 claim 就会读到新状态。只有改代码才必须重启。

**Q：还会出现"重启后进度倒退"吗？**
A：**不会了**。`startup()` 已不再回灌 SQLite（2026-09-16 收口），重启保持 MySQL 现状。所以也不用再"等没有在采任务时才敢重启"。

**Q：重跑会不会产生重复的采集结果？**
A：不会。结果表 `site_exploration_charging_station_result` 是 `ON DUPLICATE KEY UPDATE`（upsert），按站点覆盖更新。

**Q：能不能只重跑某几个站点？**
A：可以，但脚本目前是按"状态"批量重置。要精确到站点：在 MySQL 上按 `local_task_id IN (...)` 改，**记得一并清空** `lease_device_id` / `lease_token` / `lease_expires_at` / `attempt`，并统一用 `UTC_TIMESTAMP()`。改完按 §4.3 复查。
