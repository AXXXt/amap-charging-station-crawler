# 高德滑块验证后的 Shizuku 休息恢复

源码同步日期：2026-11-23。当前高德采集 App：0.1.42.27，versionCode 69，包名 com.tigercode.evcollector。下方验证记录保留原始测试日期与版本。

## 开启与流程

安装并启动 Shizuku，在采集 App 点击“授权 Shizuku”，允许后确认“已连接、已授权”。这台高德手机使用“开始重点站点详情采集”按钮启动；该入口设置重点详情模式并启动常驻采集服务，已接入本次滑块恢复流程，恢复后继续重点站点详情采集。检测到滑块或滑块重试页面时：

1. 停止当前页面采集，不点击验证重试，不进行辅助滑动。
2. 退出当前采集调用并停止任务续租；持久保存待释放租约。监控与跨平台补采任务调用现有 release 接口退回队列，不标记完成、不计作采集失败，也不因此另行生成跨平台补采。普通 NORMAL 队列暂不支持 release，使用既有 fail/retry 协议提交重试。
3. 确认租约已释放或已失效后，通过 Shizuku 强行停止 com.autonavi.minimap，核验 stopped=true 且该用户的地图主进程及子进程均为 0。返回采集 App 成功后，才开始 120 秒休息。
4. 休息结束打开高德，确认高德进入前台后，才开始 60 秒等待。
5. 两段等待全部结束，继续领取任务采集。若仍出现滑块，再次执行同一流程。

任务释放、Shizuku 关闭或打开高德失败时保持暂停，显示原因并重试；不会提前计时或领取新任务。账号封禁等异常仍走人工暂停，不以重启替代处理。原有批次节奏与访问限速保留。

## 停止与重建

- 手动停止或收到全部停止指令会取消恢复与闹钟，不会等待结束后自行重新开启采集；未确认释放的旧租约保留，下一次启动前先核实释放。
- 两段截止时间使用 elapsedRealtime 与 BOOT_COUNT 保存；同一次开机的进程重建不会重新缩短等待。跨开机的旧 elapsed 时间不能直接复用，会重新进入关闭阶段。
- “立即同步”与本地扫描遇到滑块也不再辅助滑动；自动两段等待续采由常驻设备调度执行。
- 恢复期间 App 内“打开高德地图”入口受保护，需要提前结束时先停止运行。
- 本次没有加入息屏、解锁或额外的定时轮休。
