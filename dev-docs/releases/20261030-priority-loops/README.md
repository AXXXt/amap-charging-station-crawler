# 2026-10-30 固定站点循环采集发布

## 服务端部署

从远程仓库更新本次发布提交，保留线上环境变量与数据库配置，重启现有 API 服务。部署前先备份；实际项目路径和服务名以线上配置为准，既有记录为 /opt/amap-crawler 和 amap-api。

必须同步：

- api_server.py
- monitor_scheduler.py
- priority_station_scopes.py
- config/priority_station_scopes.json
- site_exploration_bridge.py

服务启动初始化自动为 station_monitor_batch 补充 scope_key 字段，数据库账号需具备现有建表/加列流程所需权限。无需清空、重置原任务，不要执行旧的全库建批次命令或 --close-active。

新 App 注册时会检查 priorityStationScopes；预期 BAIDU_MIN240_499 为499、AMAP_MIN240_647 为647。旧服务没有该能力时，App 会提示部署并停止领取。

首次领取时创建各自专属批次，名单固定且互不重叠。百度499站采集详情，高德647站采集列表快照。target_rounds=0 表示无限轮次，target_interval_minutes=0 表示没有轮间等待；失败重试与租约回收沿用现有机制。

部署后先检查启动日志及注册能力字段，再通知操作人员开始采集。尚未启动采集测试。
